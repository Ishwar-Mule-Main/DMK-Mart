    91→## 2. PRODUCT IDENTITY — WHAT YOU ARE BUILDING
    92→
    93→### 2.1 Business Reality
    94→DMK Mart is a **trading and distribution firm**. It purchases plastic
    95→manufactured goods (chairs, buckets, kitchenware, household items,
    96→industrial crates) from manufacturers or distributors, and sells them to
    97→B2B buyers (wholesale, credit-based) and B2C walk-in customers (counter,
    98→instant payment) in bulk, packets, pieces, sets, or single units.
    99→
   100→### 2.2 The Platform's Purpose
   101→A dedicated, owner-operated software where the owner keeps:
   102→- ALL orders (purchase + sales + returns)
   103→- ALL finance (journals, ledgers, P&L, balance sheet, trial balance)
   104→- ALL inventory (dual-stock: sellable vs damaged)
   105→- ALL party records (customers, vendors, with opening/closing balances)
   106→- Organized in a well-managed, clean, easy-to-use format.
   107→
   108→### 2.3 Core Business Rules (Immutable)
   109→| # | Rule |
   110→|---|------|
   111→| R1 | Every firm is a fully isolated universe — own products, stock, parties, books. |
   112→| R2 | Products are loaded primarily via bulk CSV/Excel upload. |
   113→| R3 | Sellable and damaged stock are ALWAYS separate. Damaged is never sold. |
   114→| R4 | Sales returns of broken items go to DAMAGED stock, never sellable. |
   115→| R5 | Purchase returns reduce damaged stock and vendor payable. |
   116→| R6 | Every transaction posts a balanced double-entry journal. |
   117→| R7 | All parties have opening and closing balances. |
   118→| R8 | B2B customers use location-first naming ("Latur Ishwar Mule"). |
   119→| R9 | B2C counter maintains a buyer directory (name + phone). |
   120→| R10 | Manufacturer vendors show own-brand products; distributors show all. |
   121→| R11 | Quantity-based bulk discounts apply in SALES only. |
   122→| R12 | 5-tier pricing: Distributor ≤ Wholesale ≤ Semi-Wholesale ≤ Retailer ≤ MRP. |
   123→| R13 | Credit sales blocked when limit exceeded or overdue past grace period. |
   124→| R14 | B2C / walk-in / personal accounts have NO credit limit. |
   125→| R15 | Currency is strictly Indian Rupees (₹ / INR). |
   126→| R16 | All documents (invoices, reports) follow A4 print standards. |
   127→| R17 | Financial year switching (e.g., FY 2025-26, FY 2026-27) is supported. |
   128→| R18 | Every order, return, payment carries a date and updates books on that date. |
   129→| R19 | Low-stock alerts trigger at configurable thresholds. |
   130→| R20 | The platform is owner-only. No user accounts. Firm = account. |
   131→
   132→### 2.4 The Seven Functional Pillars
   133→1. **Sales** — B2B invoicing + B2C counter POS + sales returns + credit control
   134→2. **Purchase** — Vendor management + PO + GRN + purchase returns + payments
   135→3. **Inventory** — Dual-stock matrix + bulk upload + low-stock alerts + movements
   136→4. **Finance & Accounting** — Double-entry journals + ledgers + TB + P&L + BS + daybook
   137→5. **Tax & Compliance** — GST (CGST/SGST/IGST) + HSN + A4 tax invoices + ITC
   138→6. **AI Intelligence** — Copilot with full platform authority + alerts + decisions
   139→7. **Dashboard & Reports** — Visual KPIs + exports (CSV/Excel) + analytics

   726→## 8. TECHNICAL ARCHITECTURE STANDARDS
   727→
   728→### 8.1 Technology Stack
   729→| Layer | Technology |
   730→|-------|-----------|
   731→| Frontend Framework | Next.js 15+ (App Router) or Vite + React 19 |
   732→| Language | TypeScript (strict mode) |
   733→| Styling | Tailwind CSS v4 + CSS custom properties (design tokens) |
   734→| UI Components | shadcn/ui + Radix UI primitives + Lucide icons |
   735→| State Management | Zustand (with persistence) or React Context |
   736→| Database | SQLite (dev) / PostgreSQL (prod) via Prisma ORM |
   737→| API | Next.js App Router API routes (REST) |
   738→| Charts | Chart.js + react-chartjs-2 |
   739→| PDF Generation | jsPDF + html2canvas (for A4 invoices) |
   740→| Export | SheetJS (xlsx) for Excel; manual CSV builder with BOM |
   741→| Fonts | Inter (body) + display font per design system |
   742→
   743→### 8.2 Data Isolation Model
   744→Every table carries a `firm_id` (or `company_id`) column.
   745→Every query filters by active firm context.
   746→No cross-firm data leakage. Ever.
   747→
   748→### 8.3 Financial Posting Rules
   749→- Every monetary event posts via a single `postJournal()` function.
   750→- `postJournal()` rejects if ΣDr ≠ ΣCr (to the paisa).
   751→- All amounts stored as DECIMAL/NUMERIC. Never float.
   752→- Journal entries are immutable after posting. Reversals create new entries.
   753→- Every journal entry carries: date, voucher type, reference document ID, narration.
   754→
   755→### 8.4 Naming Conventions
   756→- Files: kebab-case for components, snake_case for DB columns.
   757→- API routes: `/api/v1/<resource>` (RESTful, plural nouns).
   758→- DB tables: snake_case, plural (e.g., `purchase_orders`, `journal_lines`).
   759→- TypeScript types: PascalCase (e.g., `PurchaseOrder`, `JournalLine`).
